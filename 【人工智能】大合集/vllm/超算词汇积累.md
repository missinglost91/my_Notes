# CacheBlend 缓存融合

## HKVD

`HKVD` 是 **High-KV-Deviation** 的缩写，意思是：

**KV 偏差很大的 token。**

在 CacheBlend 论文里，有两种 KV：

```
KV_pre  = 这个 chunk 单独提前算好的 KV cache
KV_full = 把所有 chunk 拼起来完整 prefill 后得到的 KV cache
```

如果同一个 token 的这两种 KV 差很多：

```
|KV_pre - KV_full| 很大
```

它就是 **HKVD token**。


## cross-attention相对于self-attention

严格说，在 decoder-only LLM 里它还是 self-attention。论文里说的 cross-attention，是指：

**不同 chunk 之间的 attention。**

比如：

```
chunk1: Messi scored 13 goals.
chunk2: Ronaldo scored 8 goals.
```

当 `chunk2` 里的 `8` 看向 `chunk1` 里的 `13`，这就是跨 chunk 的 attention。

## selective recompute 

`selective recompute` 就是 **选择性重算**。

在 CacheBlend 里，完整 prefill 是：

```
所有 token 的 KV 都重新算
```

full KV reuse 是：

```
所有 token 的 KV 都不重算，直接复用旧缓存
```

CacheBlend 走中间路线：

```
大部分 token 的 KV：直接复用
少部分关键 token 的 KV：重新计算
```

重算那些 **KV_pre 和真实上下文下 KV 差异大** 的 token，也就是 HKVD tokens。

**RoPE 位置修正 + selective recompute 补 cross-attention**

更准确地说，一层 self-attention 大概是这样：

```
输入 hidden states
   ↓
线性层计算 Q, K, V
   ↓
对 Q 和 K 加 RoPE 位置信息
   ↓
用 Q 和 K 算 attention score
   ↓
用 attention score 加权 V
   ↓
得到 attention 输出
```

所以 RoPE 和 Q/K/V 不是两套独立流程。它们是在 self-attention 里面一起工作的。

**8. 系统流水线为什么重要**

如果只是“复用 KV + 重算 15% token”，还不一定足够快，因为 KV cache 可能很大，从 CPU/SSD 搬到 GPU 也要时间。

CacheBlend 的系统洞察是：

```
加载 KV cache 和局部重算可以并行
```
